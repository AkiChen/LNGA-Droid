# LNGA Android：AI 与系统体验分阶段迁移计划

- 状态：阶段 1 已在 0.14.0 完成真机验收；阶段 2 已完成真实服务商验收；阶段 3 已在 0.16.0 完成真机验收；阶段 4 已在 0.17.0 实现；阶段 5 已在 0.18.0 实现并待真机/真实账号验收；阶段 6–9 待实施
- 制定日期：2026-08-26
- 对照目标：LNGA HarmonyOS 主体的 AI 对话、帖子总结、用户成分分析、TTS、自适应布局、系统设置与智感握姿
- 实施原则：每个阶段独立可用、可测试、可发布；不为后续阶段提前暴露空入口

## 范围与既有约束

本路线包含：

- AI 服务商配置、流式对话、帖子总结、用户成分/政治光谱分析
- 字体、图片加载策略、缓存管理、通用内置浏览器
- Android TTS 帖子朗读
- 手机/平板宽度自适应与后期的可选智感握姿
- 相关安全、隐私、诊断、持久化和测试基础设施

继续遵守已经确认的产品决定：

- 手机端保持竖屏锁定；平板横屏策略在自适应阶段单独确认，不在前期擅自解除锁定。
- 不恢复“选页按钮随手机倾斜移动”。智感握姿若实现，只用于可选的单手布局辅助，默认关闭。
- AI API Key、NGA 凭证和用户内容不得进入普通日志、图片诊断或崩溃报告。
- 设置必须持久化；退出 NGA 登录不应删除 AI 配置、主题、历史、收藏或系统体验设置。

## 阶段 1：设置架构与媒体可靠性

实施状态：0.14.0 已完成代码、单元测试、Lint 和 APK 构建，旧图床/CDN 恢复与网络策略仍需 OPPO 真机验证。

### 用户可见结果

- 将当前弹窗式浏览设置升级为可扩展的设置页面。
- 增加字体大小、图片加载模式、缓存占用与清理入口。
- 图片加载模式支持：始终加载、手动加载、仅 Wi-Fi 自动加载。
- 完成 `BACKLOG.md / IMG-001`：旧 NGA 图床迁移、CDN 43 字节占位图识别和有限重试。
- 增加通用内置网页浏览器开关；NGA/Bilibili/微博等链接按规则选择内置或外部打开。

### 技术工作

- 建立类型化设置仓库和版本迁移机制，替代继续散落 SharedPreferences 键值。
- 抽离网络状态、缓存统计、图片请求策略和 WebView 导航策略。
- 保留现有设置值，升级安装后不得恢复默认值。

### 验收标准

- 杀进程、重启、退出再登录后设置不丢失。
- 移动网络和 Wi-Fi 下图片策略符合设置。
- 旧图床样例能够展示、放大和下载；CDN 占位图不会作为正文图片显示。
- 清除媒体缓存不清除账号、收藏、历史或 AI 配置。

## 阶段 2：AI 服务商与安全配置基础

实施状态：0.15.0 已完成配置管理、Keystore 加密、模型列表、连接测试和错误映射；0.15.1 修复新建配置保存按钮被空闲状态误判为忙碌的问题。真实 API Key 与服务商端到端测试由用户验收。

### 用户可见结果

- 新增 AI 设置页：创建、编辑、删除、启用配置。
- 首批支持 OpenAI-compatible 自定义服务商，并提供 DeepSeek、智谱 GLM、豆包、MiniMax、Kimi、OpenAI 预设参数。
- 支持连接测试、模型列表读取和手工填写模型名。
- API Key 只显示掩码，可独立删除或替换。

### 技术工作

- 定义 `AiProvider`、`AiConfig`、`AiRequest`、`AiStreamEvent` 和统一错误模型。
- 复用 Android Keystore AES-GCM 方案加密保存 API Key；普通设置只保存非敏感元数据。
- 为服务商能力建立声明：Chat Completions、Responses、流式协议、模型列表、联网搜索能力。
- 网络日志只记录服务商、阶段、状态码、耗时和脱敏错误，不记录 Key、提示词和回复正文。

### 验收标准

- 至少一个预设服务商和一个自定义 OpenAI-compatible 地址通过连接测试。
- 错误 Key、超时、限流、模型不存在、返回格式异常均有明确中文提示。
- 本地备份、日志和诊断报告中搜索不到明文 API Key。

## 阶段 3：通用 AI 流式对话

实施状态：0.16.0 已完成多轮流式对话、停止/重试、本地会话历史、上下文裁剪和增量 Markdown；真实服务商流式兼容性与长回复滚动由用户真机验收。

### 用户可见结果

- 增加独立 AI 对话页，支持多轮消息、流式输出、停止生成和重新发送。
- AI 内容使用增量 Markdown 渲染，支持代码块、列表、引用和链接。
- 支持新建会话和清空当前会话；会话历史先仅保存在本机。

### 技术工作

- 将网络流解析、会话状态和 Compose UI 解耦，避免每个 token 导致整页重组。
- 正确处理取消、页面退出、进程重建和并发请求。
- 对上下文条数和正文长度设置上限，并显示即将发送的大致数据范围。

### 验收标准

- 流式请求可以随时停止，停止后不会继续写入 UI。
- 旋转策略、后台切换和返回页面不会造成重复请求或崩溃。
- 长回复滚动稳定，代码块和中文 Markdown 可读。

## 阶段 4：帖子 AI 总结

实施状态：0.17.0 已实现当前页/整个主题范围确认、页面缓存、分阶段进度、取消、BBCode 语义导出、去重与字符预算，并将结果接入本地 AI 会话供继续追问。同期加入按 UID 保存的已读标记和可选楼层续读。

### 用户可见结果

- 主题页增加“AI 总结”入口。
- 加载过程显示：收集楼层、整理正文、裁剪上下文、请求 AI、生成总结。
- 默认总结当前已加载范围；若要拉取更多页面，必须明确显示范围和网络成本。
- 结果进入 AI 对话页，用户可以继续追问。

### 技术工作

- 建立 BBCode/媒体到纯文本的稳定导出器，引用、表格和链接保留可理解语义。
- 去除头像 URL、Cookie、诊断字段等无关或敏感信息。
- 对超长主题进行分段、去重和预算控制；不静默发送整个超长主题。

### 验收标准

- 普通主题、长主题、图片为主主题和表格主题均能给出明确结果或可理解的限制提示。
- 同一页面重复总结不会重复抓取已经缓存的楼层。
- 用户取消后，抓取和 AI 请求都停止。

## 阶段 5：用户主页、活动统计与用户光谱

实施状态：0.18.0 已加入楼层用户入口、公开资料、最多三页且每类最多 100 条的主题/回复样本、版面与东八区时段统计，以及发送前字段确认和 AI 推断声明。同批完成全局 AI 任务状态浮层、增量 Markdown 补强与主题标题慢速跑马灯；真实账号的资料字段差异、隐藏记录和限流仍需真机验收。

0.18.1 将浮动 AI 状态球收回主题列表、主题和用户资料页顶栏，并为会话持久化 `TopicSummary/tid` 与 `UserAnalysis/uid` 来源。当前对象的状态图标只打开其对应结果；重新生成会替换同来源旧会话。同期把主题收藏移入标题长按菜单，并为默认等宽展示的长图增加上下黑色安全留白。

0.19.0 将主题摘要入口收敛为星星状态机：未生成时确认创建、生成中闪烁、完成后显示纯金色星星；点击打开当前主题会话，长按确认重新生成。会话标题直接保留真实主题标题，对话面板增加四角圆角和底部安全区适配。同期为回复加入保守的 Markdown 自动识别，并新增小红书图文/视频摘要卡片。

0.19.1 移除下拉式 AI 对话弹窗，主题摘要、用户光谱和最近会话统一进入全屏 `AiChatScreen`；准备摘要时使用独立全屏进度状态，避免显示旧会话。顶栏状态入口改为原创单色玻璃棱镜：空闲为低亮冰蓝、处理中暗亮循环、完成后为纯金色，保留点击打开与长按重新生成语义。

0.20.0 将顶栏状态入口重新设计为适配明暗主题的单个圆弧四芒星：未生成显示灰色、处理中仅在星形内部流动彩色渐变、完成后显示金色。AI 会话按会话持久化模型选择，标题改为慢速跑马灯，新建/删除移入标题长按菜单，模型切换和历史入口保留在外部；摘要标题不再显示服务商或模型副标题。

0.20.1 将 AI 会话输入区改为悬浮胶囊布局，并改由窗口统一处理输入法避让，避免 OPPO/Android 16 上重复计算 IME 高度产生大块空白。帖子页浮动分页的中间页码增加吸附式滚轮选择，可直接跳转到任意页面。

0.21.0 增加会话级联网搜索开关，OpenAI、Model Gate 和火山方舟使用 Responses API 的托管 `web_search`，强制执行搜索并校验搜索调用与来源链接；同时兼容 JSON 和 SSE 响应。已有 `api.model-gate.com/v1` 自定义配置自动获得搜索能力，其他兼容服务可在配置编辑页手动声明。AI 聊天内容与输入栏改为同一 IME 避让布局，修复 OPPO Android 16 上键盘覆盖输入栏的回归。

0.21.1 补齐 `mg.aid.pub` ModelGate 的自动识别及独立 `/responses/v1/responses` 路由，联网搜索入口改为常显，模型切换菜单去除配置名称。AI 设置增加配置复制，API Key 在 Keystore 内重新加密到新配置。成功生成用户光谱的用户头像显示金色 AI 标记，资料页直接渲染最近一次成功结果；重新生成失败时保留旧结果，成功后再替换旧会话。

0.22.0 根据实际兼容性反馈移除实验性的会话联网搜索入口、配置声明和 Responses `web_search` 请求，旧配置及会话中的搜索标记会被安全忽略；普通 AI 对话与模型切换保持不变，后续联网能力改由独立搜索插件承载。同批增加抖音短链/直链摘要卡片、退出登录二次确认，以及可持久化调节的双上滑间隔和距离阈值。

### 用户可见结果

- 先补齐用户主页/用户卡片基础入口，包括用户主题、回复和公开资料。
- 展示可验证的本地统计：主题数、回复数、活跃版面、发帖时段、近期标题和回复片段。
- 用户确认发送的数据后，可进入“AI 成分分析”，输出用户画像、兴趣领域、政治光谱和整体点评。
- 统计事实与 AI 推断在界面中明确分区，避免将推断显示成客观资料。

### 技术工作

- 移植 `UserApi.getUserActivityAnalysis` 对应的数据抓取、分页、限流和聚合逻辑。
- 用户分析复用阶段 2–4 的服务商、流式 UI、纯文本和预算机制。
- 默认只处理公开内容并限制样本数量；发送前展示字段清单。

### 验收标准

- 无公开记录、匿名用户、被隐藏内容、接口限流均有独立状态。
- 活跃版面和时段统计可用固定样本做确定性单元测试。
- AI 结论明确标记为模型推断，并提供“仅查看统计，不发送 AI”路径。

## 阶段 6：Android 帖子语音朗读

### 用户可见结果

- 主题页支持从指定楼层开始朗读、暂停、继续、上一段、下一段和停止。
- 设置页支持语速、音调、朗读签名/引用与否，以及系统语音引擎选择入口。
- 超长帖子自动分段衔接，并显示当前楼层与段落进度。

### 技术工作

- 使用 Android `TextToSpeech`，建立进程内唯一播放协调器。
- BBCode 转朗读文本时跳过图片 URL、视频地址、表格排版符和重复引用。
- 页面离开、来电/音频焦点变化、引擎缺失和语言包缺失时正确处理生命周期。

### 验收标准

- 中文长帖连续朗读不截断、不重复楼层。
- 停止后立即释放队列；重新进入主题不会自动续播，除非后续明确增加该设置。
- 引擎不可用时给出系统设置入口，而不是静默失败。

## 阶段 7：手机/平板自适应布局

### 用户可见结果

- 手机继续使用当前单栏导航。
- 大屏设备逐步启用板块/主题双栏、主题/楼层双栏，以及更合理的图片和正文最大宽度。
- 字体缩放、系统导航栏、刘海和分屏模式下布局不溢出。

### 技术工作

- 以窗口宽度等级和实际可用宽度驱动布局，不以设备型号硬编码。
- 拆分当前大型 `LngaApp.kt`，将页面、导航状态与可复用卡片组件分层。
- 首先实现同一 Activity 内自适应；平板是否允许横屏在该阶段由用户确认。

### 验收标准

- 手机宽度回归测试不改变现有主要操作位置。
- 平板与分屏模式可以在列表和详情间保持选择、滚动与分页状态。
- 大字体下标题、分页按钮和设置项不重叠。

## 阶段 8：可选智感握姿与单手模式

### 用户可见结果

- 设置页增加“单手布局辅助”，默认关闭。
- 可根据稳定的左/右持握判断，将刷新、回复等主要浮动操作放到易触达一侧。
- 提供固定左侧、固定右侧和关闭选项。

### 技术工作

- 优先使用重力/加速度传感器的低频采样、滞回和稳定时间，避免 UI 左右抖动。
- 页面不可见或功能关闭时停止监听。
- 不控制分页按钮，不改变滚动行为，不申请与功能无关的权限。

### 验收标准

- 走路、轻微晃动和桌面平放不会频繁切边。
- 关闭后零传感器监听；固定侧模式完全不受传感器影响。
- OPPO 真机功耗与操作稳定性单独验证。

## 阶段 9：整体验收与发布收口

### 工作内容

- 检查升级迁移、配置损坏恢复、缓存边界、后台生命周期和低内存行为。
- 为各阶段建立可重复的单元测试、MockWebServer 测试和真机验收表。

### 最终验收矩阵

- Android 8/API 26 与 Android 16/API 36 基础兼容。
- OPPO 手机：登录、AI 流式输出、帖子总结、用户分析、TTS、图片和 VPN 场景。
- 手机竖屏、大字体、深色模式、Wi-Fi/移动网络/VPN、后台恢复。
- 每次发布执行 parser tests、app unit tests、Lint、APK 构建、签名/版本/SHA-256 校验和 Google Drive 上传复核。

## 建议实施顺序与阶段依赖

```text
阶段 1 设置与媒体可靠性
  ├─> 阶段 2 AI 配置
  │     └─> 阶段 3 AI 对话
  │            ├─> 阶段 4 帖子总结
  │            └─> 阶段 5 用户光谱
  ├─> 阶段 6 TTS
  └─> 阶段 7 自适应布局
            └─> 阶段 8 智感握姿

全部完成 ─> 阶段 9 收口验收
```

推荐严格按 1 → 2 → 3 → 4 → 5 → 6 → 7 → 8 → 9 推进。阶段 4 和阶段 5 共用 AI 基础，但帖子总结的数据链已经存在，风险低于用户活动抓取，因此先做帖子总结更合适。

## 每阶段协作方式

1. 开始编码前，先确认该阶段的 UI 草图、默认值和不做事项。
2. 实现过程中只扩展本阶段范围；新发现的问题进入 `BACKLOG.md`，不顺手扩大版本。
3. 编译前先提交本阶段变更摘要和真机测试路径。
4. 构建通过后生成独立版本 APK，完成本地校验和 Google Drive 上传。
5. 用户按验收清单真机测试；问题关闭后再进入下一阶段。
